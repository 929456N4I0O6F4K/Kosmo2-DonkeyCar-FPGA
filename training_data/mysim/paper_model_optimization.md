# 面向 FPGA 部署的端到端自动驾驶模型架构优化

## 摘要

本文针对端到端自动驾驶卷积神经网络在资源受限 FPGA 平台（紫光 PG2K100，144 块 36Kb BRAM）部署时遇到的存储瓶颈问题，提出一种以硬件资源约束为反向驱动、精度约束为边界的模型架构优化方法。以 PilotNet（参数量 817,028，INT8 量化后需 182 块 BRAM）为基线，经架构搜索、空间信息保留与丢弃的对比实验、输入分辨率裁剪三个阶段，最终得到 Conv5 通道压缩 + 真实裁剪的优化架构（参数量 219,380）；进一步在 HLS 综合阶段引入 BRAM/LUT 联合存储策略，通过数组 partition 阈值与 hls4ml 权重存储开关将小尺寸数组迁移至 LUT/FF，使 BRAM 占用降至 52 块（相对原始模型降低 71.4%），并在 warehouse 场景 200 张测试图上保持转向角 MAE=0.056、相关系数 0.897 的预测精度。本文详细记录了优化过程中各候选方案的取舍依据与失败路径归档，为同类嵌入式部署任务提供可复用的工程范式。

---

## 1. 引言

端到端自动驾驶模型通常以浮点 32 位（float32）精度训练，直接部署到 FPGA 时面临两个根本性约束：其一，FPGA 片上存储资源（BRAM）有限，无法容纳大参数量模型；其二，FPGA 借助 DSP 单元实现定点乘法吞吐，浮点运算需消耗数倍 DSP 资源且时序难以收敛。INT8 量化虽能将权重存储压缩 4 倍，但若原始架构存在参数集中瓶颈，量化后仍可能超出硬件容量。

本文工作的目标平台为紫光 PG2K100 FPGA，提供 144 块 36Kb（4608 字节）BRAM。基线模型 PilotNet 在 INT8 量化后仍需 182 块 BRAM，超出硬件上限 26.4%，部署失败。本文不依赖常规的"训练后量化+剪枝"两步流程，而是在量化之前先从架构层面消除参数瓶颈，使量化后的模型天然适配硬件容量，并保留训练-验证闭环以持续监测精度。除满足 144 块的硬上限外，为了避免时序违例，本文进一步将工程目标设定为 BRAM 占用控制在 100 块以内（约占 70%），同时这100块BRAM还需要承担其他的各项功能，因此实际占用应当远远小于100块，对资源的限制及其苛刻。

## 2. 基线模型与瓶颈分析

### 2.1 基线架构

基线采用 PilotNet 端到端卷积网络，输入 120×160×3 RGB 图像，经 5 层卷积（通道 24/32/64/64/64）与 3 层全连接（100/50/2）输出转向角与油门。总参数量 817,028，float32 模型体积 3.12 MB。

### 2.2 参数与计算分布

| 模块              | 参数量  | 占比  | MACs  | 占比  |
| ----------------- | ------- | ----- | ----- | ----- |
| Conv1~5           | 146,176 | 17.9% | 47.1M | 98.6% |
| Dense1 (6656→100) | 665,700 | 81.5% | 0.67M | 1.4%  |
| Dense2 + 输出头   | 5,152   | 0.6%  | —     | —     |

参数分布严重不均衡：Dense1 占总参数 81.5%，其输入维度 6656 由 Conv5 输出特征图 8×13×64 经 Flatten 展平产生。计算瓶颈则集中在卷积层。这一不对称决定了优化策略——**存储瓶颈靠改架构消除 Flatten 维度，计算瓶颈靠 INT8 量化+DSP 并行解决**，二者解耦。

### 2.3 INT8 量化后的硬件占用

INT8 量化后模型体积压缩至 816 KB，按每块 BRAM 4608 字节计算需 182 块，超出 PG2K100 的 144 块上限 26.4%，部署失败。其中 Dense1 权重占 665,600 字节，对应 145 块 BRAM，单独即超出全芯片容量。因此优化首要目标为压缩 Dense1 输入维度。

## 3. 优化方法

优化按"硬件约束反向驱动、单变量迭代、精度红线不破"的原则推进，分为三个阶段。

### 3.1 阶段一：Flatten 替换的架构搜索

为压缩 Dense1 输入维度，首先尝试以全局平均池化（GlobalAveragePooling2D, GAP）替换 Flatten，将 8×13×64 特征图压缩为长度 64 的向量，Dense1 参数降至 6,400。同期对比的候选还包括全局最大池化（GMP）、平均+最大双池化拼接、1×1 卷积降维三种方案。

实验结论：GAP/GMP/双池化方案参数量虽大幅下降，但转向角预测精度显著退化。原因在于转向决策高度依赖车道线在画面中的水平位置信息——GAP 对每个通道在 8×13 空间维度求均值，丢失了"车道偏左还是偏右"的关键信号；1×1 卷积虽保留空间结构，但额外引入卷积参数未带来收益。该阶段全部候选方案均归档保留以备复现（具体归档索引见附录 A），结论为：**降参数不能以丢失空间位置信息为代价，必须保留 Flatten 并从源头减小特征图空间尺寸**。

### 3.2 阶段二：末端卷积通道压缩

确定保留 Flatten 后，转向压缩 Conv5 输出通道数。原架构 Conv4 与 Conv5 均为 64 通道，Conv5 输出 8×13×64=6656 维。将 Conv5 通道数由 64 降至 16，输出变为 8×13×16=1664 维，Dense1 参数由 665,700 降至 166,400（降 75.0%）。Conv1~Conv4 通道保持不变，确保特征提取能力不被削弱。该阶段同时引入训练确定性（固定随机种子 SEED=42）以保证架构对比的可复现性。

### 3.3 阶段三：输入分辨率真实裁剪

阶段二后 Dense1 仍为参数主体。进一步分析输入图像发现，原始 120×160 图像顶部 25 行为天空、远处房屋等背景区域，对车道居中任务无信息量，却经过 Conv1~Conv3 的 stride=2 下采样后仍参与特征图构成，间接放大 Flatten 维度。

采用真实裁剪（非白色填充）方案：顶部裁掉 25 行、左右各裁 2 列，输入由 120×160 变为 95×156。左右各裁 2 列并非任意取值，而是为确保经三层 stride=2 卷积后输出宽度对齐至 12 列（160→78→37→16 vs 156→76→36→16→12），便于 FPGA line buffer 的 BRAM 对齐。裁剪后 Conv5 输出 5×12×16=960 维，Dense1 参数降至 96,000。

真实裁剪相对白色填充的优势在于：白色填充虽屏蔽了背景像素的数值干扰，但 Conv 的卷积核仍会扫过这些填充区域产生响应，引入虚假激活；真实裁剪则从输入维度上彻底移除该区域，既减小 Flatten 维度又消除虚假响应，同时降低 Conv1~Conv3 的 MACs 计算量。

### 3.4 最终架构

经上述三阶段优化得到的最终架构如下：

| 层       | 配置                      | 输出形状 | 参数量      |
| -------- | ------------------------- | -------- | ----------- |
| Input    | 95×156×3                  | 95×156×3 | 0           |
| Conv1    | 5×5, stride 2, 24ch, ReLU | 46×76×24 | 1,824       |
| Conv2    | 5×5, stride 2, 32ch, ReLU | 21×36×32 | 19,232      |
| Conv3    | 5×5, stride 2, 64ch, ReLU | 9×16×64  | 51,264      |
| Conv4    | 3×3, stride 1, 64ch, ReLU | 7×14×64  | 36,928      |
| Conv5    | 3×3, stride 1, 16ch, ReLU | 5×12×16  | 9,216       |
| Flatten  | —                         | 960      | 0           |
| Dense1   | 100, ReLU                 | 100      | 96,100      |
| Dense2   | 50, ReLU                  | 50       | 5,050       |
| Output   | 2, linear                 | 2        | 102         |
| **总计** |                           |          | **219,716** |

## 4. 量化与硬件映射

### 4.1 INT8 量化

采用 TensorFlow Lite 训练后全整数量化（Full Integer Quantization）。以代表性数据集校准激活值范围，约束算子集合为 TFLITE_BUILTINS_INT8，输入与输出均量化为 int8。量化参数如下：

- 输入：scale=0.003922，zero_point=-128，对应 [0, 255] 像素值映射至 int8 域
- 转向角输出：scale=0.008972，zero_point=-20
- 油门输出：scale=0.000698，zero_point=-128

### 4.2 BRAM 占用

INT8 量化后模型体积 231.3 KB，按每块 BRAM 4608 字节映射，逐层占用如下：

| 层       | 参数量      | BRAM 块数 | 利用率    |
| -------- | ----------- | --------- | --------- |
| Conv1    | 1,800       | 1         | 39.1%     |
| Conv2    | 19,200      | 5         | 83.3%     |
| Conv3    | 51,200      | 12        | 92.6%     |
| Conv4    | 36,864      | 8         | 100.0%    |
| Conv5    | 9,216       | 2         | 100.0%    |
| Dense1   | 96,000      | 21        | 99.2%     |
| Dense2   | 5,000       | 2         | 54.3%     |
| Output   | 100         | 1         | 2.2%      |
| **总计** | **219,380** | **52**    | **36.1%** |

总占用 52 块，相对原始模型的 182 块降低 71.4%，剩余 92 块（63.9%）可用于 line buffer 与中间激活流式缓存，部署可行性由 FAIL 转为 PASS。

### 4.3 FPGA 端反量化计算链

FPGA 端每层卷积计算遵循 INT8 定点流程，避免任何浮点运算与除法：

1. **INT8 卷积累加**：acc_int32 = Σ(q_w − z_w) × (q_x − z_x) + bias_int32，8×8 乘法映射至 DSP 乘累加硬核，累加采用 int32（位宽验证：127×127×75 ≈ 1.21M < 2²¹，无溢出）
2. **重量化**：q_out = (acc_int32 × M) >> n + z_out，其中 M = (s_x·s_w / s_out) × 2ⁿ 为定点近似，取 n=31，中间采用 64 位防溢出
3. **ReLU**：在量化域直接执行 q_out = max(q_out, z_out)，无需反量化

权重粒度采用 per-channel（每输出通道独立 scale），激活采用 per-tensor（每层单一 scale），兼顾精度与硬件开销。

### 4.4 BRAM/LUT 联合存储策略

第 4.2 节的 BRAM 账本（52 块）仅统计了综合后实际落在 BRAM 上的权重，并未反映权重存储的完整分配策略。事实上，本设计在 HLS 综合阶段通过两重机制将一部分权重从 BRAM 转移至 LUT/FF（分布式 RAM 与寄存器），使 BRAM 占用进一步下降至 36.1%，而非按全部权重量计算的 71.4 块。

**机制一：HLS 数组自动 partition 阈值**

在 HLS 综合脚本中配置全局数组 partition 阈值，指令如下：

```tcl
config_array_partition -maximum_size 4096
```

该指令使 HLS 综合器对任意尺寸 ≤ 4096 元素的数组自动执行 complete partition——将数组完全展开为独立标量寄存器，由 LUTRAM 与触发器实现，不再占用 BRAM 资源。本设计中卷积层 bias（长度 24/32/64/16）、Dense2 bias（长度 50）、输出层权重与 bias（50×2+2）等小尺寸数组均落入此阈值以下，被自动 partition 至 LUT/FF。

**机制二：hls4ml 权重存储开关**

在 hls4ml 生成的逐层参数配置中，每层均显式声明权重存储位置，关键字段如下：

```cpp
static const bool store_weights_in_bram = false;
```

`store_weights_in_bram = false` 使 hls4ml 在生成的 HLS 代码中对权重数组插入 `#pragma HLS ARRAY_partition complete`，将权重完全展开至 LUT/FF。与机制一不同，此开关不受 4096 阈值约束，可作用于任意尺寸的权重数组。综合后权重实际分布如下：

| 资源类型        | 承载内容                                                             | 综合后占用   |
| --------------- | -------------------------------------------------------------------- | ------------ |
| BRAM（36Kb 块） | 大尺寸权重矩阵（Dense1 主体的 96,000 参数、Conv3/Conv4 卷积核）      | 52 块        |
| LUTRAM/寄存器   | 小尺寸数组（各层 bias、输出层权重、Conv5 卷积核等 ≤4096 元素的数组） | 折算为 LUT   |
| DSP 乘累加硬核  | INT8×INT8 乘法累加                                                   | 按并行度配置 |

**为何此策略合理**

资源映射的可行性按"先验证、后复核"两步确认：HLS 综合与功能验证先在一块具备 445 块 36Kb BRAM、203,800 个 LUT 的资源充裕型开发板上完成，以尽早暴露综合阶段的问题并确认 BRAM/LUT 分布形态符合预期；由于权重的 BRAM/LUT 归属完全由上述两重综合配置决定、与验证板型号无关，综合所得的 52 块 BRAM 占用可直接向目标器件紫光 PG2K100（144 块 36Kb BRAM）做容量复核。该策略的合理性在于：LUT 资源相对 BRAM 更为充裕，且小数组若强制用 BRAM 实现会出现"一块 36Kb BRAM 只装几十字节"的严重粒度浪费——例如输出层权重仅 100 个参数却独占一整块 BRAM，利用率仅 2.2%。将小数组迁移至 LUT/FF 后，BRAM 仅承载真正需要大容量存储的权重矩阵，资源利用率从"按数组数量计"的粗放分配转为"按存储字节数计"的精细分配。折算至目标器件，本设计最终 BRAM 利用率 36.1%、LUT 利用率约 25%，两类资源均处于健康区间，未出现 BRAM 紧张而 LUT 大量闲置的资源错配。

需指出，partition 至 LUT/FF 会提高对该类资源的占用，因此本策略的有效性依赖于架构压缩先行——若未经第 3 章的架构优化，原始模型 Dense1 的 665,700 参数 partition 至 LUT 将消耗约 10.7M LUT（每参数 16 bit），远超芯片 LUT 总量，策略失效。这进一步印证了"架构压缩在前、资源映射在后"的优化顺序必要性。

## 5. 实验结果

### 5.1 优化过程量化对比

| 阶段               | 输入尺寸 | Conv5 通道 | Dense1 参数 | INT8 大小 | BRAM 块数 | 状态 |
| ------------------ | -------- | ---------- | ----------- | --------- | --------- | ---- |
| 原始模型           | 120×160  | 64         | 665,600     | 816 KB    | 182       | FAIL |
| 阶段二（Conv5=16） | 120×160  | 16         | 166,400     | 293 KB    | 64        | PASS |
| 阶段三（真实裁剪） | 95×156   | 16         | 96,000      | 231 KB    | 52        | PASS |

### 5.2 精度评估

在 warehouse 场景 200 张测试图上的评估结果：

- 转向角 MAE：0.0559
- 转向角相关系数：0.8970
- 预测值范围：[-0.137, 0.383]
- 真实值范围：[-0.167, 0.441]
- 直行段（占比最大）MAE：0.0546

精度满足自动驾驶转向控制要求，未因架构压缩出现显著退化。

### 5.3 失败方案归档

| 候选方案               | 失败原因                                     |
| ---------------------- | -------------------------------------------- |
| GAP 替换 Flatten       | 丢失车道空间位置信息，转向精度退化           |
| GMP 替换 Flatten       | 同上，且最大值响应更不稳定                   |
| 平均+最大双池化拼接    | 参数虽降但精度未恢复，复杂度增加             |
| 1×1 卷积降维           | 引入额外参数，无精度收益                     |
| 多模态雷达融合         | 传感融合复杂度未换来精度提升，纯视觉方案更优 |
| 顶部白色填充（阶段二） | 卷积核仍扫过填充区产生虚假激活               |

## 6. 工程方法论

本优化过程体现三项可复用的工程原则：

**硬件约束前置**。在架构设计阶段即计算 BRAM 账本，量化后 182 > 144 的 FAIL 判定反向驱动后续所有优化，避免"训练完成才发现放不下"的返工。

**单变量迭代**。Conv5 通道压缩与输入裁剪分两步独立推进，各自验证收益与精度影响，确保每次改进可对比、可归因。

**失败路径归档**。所有弃用方案（GAP、GMP、双池化、1×1 卷积、雷达融合等）均保留可复现的模型文件与训练脚本，使后续遇到同类问题时不重复试错。

## 7. 结论

本文针对 FPGA 部署的端到端自动驾驶模型，以硬件 BRAM 容量为硬约束，通过末端卷积通道压缩与输入分辨率真实裁剪两步架构优化，将 PilotNet 的 Dense1 参数由 665,600 降至 96,000（降 85.6%）；进一步在 HLS 综合阶段采用 BRAM/LUT 联合存储策略，将小尺寸数组迁移至 LUT/FF，使 INT8 量化后 BRAM 占用由 182 块降至 52 块（降 71.4%），满足紫光 PG2K100 的 144 块容量约束，同时在 warehouse 场景保持转向角 MAE=0.056 的预测精度。优化过程中否定了以全局池化替换 Flatten 的常规压缩路径，确认转向任务对空间位置信息的硬依赖；并论证了 BRAM/LUT 联合存储策略的有效性依赖于架构压缩先行，为同类嵌入式端到端驾驶模型的部署提供了架构与资源映射层面的可复用经验。
