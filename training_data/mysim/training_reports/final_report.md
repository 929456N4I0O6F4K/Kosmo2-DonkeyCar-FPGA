# Donkey Car 视觉转向模型训练与 FPGA 部署技术报告

*95×156 裁剪输入 · 5 层卷积 + 3 层全连接 · 全 INT8 量化 · RO-PUF 权重绑定*

- 硬件平台：紫光 PG2K100 FPGA（144 块 DRAM36K）
- 数据规模：5673 帧 / 6 个 session；4717 帧同帧对齐评估
- 模型规模：219,732 参数 · INT8 体积 231.1 KB
- 定点推理：17.60 ms / 帧 @ 50 MHz，时序全约束满足
- 报告日期：2026-11-02

## 摘要

本报告描述一个面向 FPGA 车载部署的视觉转向模型：模型以单目摄像头画面为唯一输入，直接回归转向角与油门两个量；网络结构、输入尺寸与量化格式均由目标器件的存储预算反向约束确定，训练侧的全部工作都在**不改动网络结构一个参数**的前提下进行。

| 指标                            | 结果                                          |
| ------------------------------- | --------------------------------------------- |
| 角度 MAE（4717 帧）             | **0.2107**                                    |
| 角度 RMSE                       | 0.2847                                        |
| 角度相关系数                    | 0.8860                                        |
| 急弯 MAE（\|t\|≥0.5，n=2757）   | **0.1865**                                    |
| 极限弯 MAE（\|t\|≥0.9，n=1709） | **0.1674**                                    |
| 急弯欠转率                      | 25.57%                                        |
| INT8 相对 FP32 角度偏差         | MAE 0.0048 / P95 0.0119                       |
| 权重体积                        | FP32 864.9 KB → INT8 231.1 KB（3.74×）        |
| 单帧推理                        | 17.60 ms @ 50 MHz，setup slack +4.306 ns      |
| PUF 绑定强度                    | 128 位响应 + 16 位校验，作用于 144 个乘加抽头 |

整套方案由三条主线构成：

1. **标签可信化**：行车数据的人工打角标签含反应延迟、手柄抖动与过冲修正三类系统性噪声，先用时间对齐、中值滤波、剔除修正帧三步清洗，保证「标签说的是图像里正在发生的事」。
2. **分布治理**：原始数据急右占比 40.7%，直接训练会让容量被单一分箱吞掉；用分箱均衡过采样 + 代价敏感加权 + 门控欠转惩罚，把优化压力导向「大弯打够、直行打稳」这两个安全边界。
3. **成像退化覆盖**：帆布赛道的反光白斑、褶皱弯线、标线老化、邻道干扰线等退化在训练集里样本稀少，用 23 项与物理成因对齐的增强 + 成对镜像把它们补进训练分布。

最终模型在整卷 4717 帧上角度 MAE 0.2107、相关系数 0.8860；在最危险的大幅值区间（|t|≥0.9）MAE 压到 0.1674，急弯欠转率 25.57%。量化到 INT8 后相对浮点模型的输出偏差仅 0.0048（P95 0.0119），体积压缩 3.74 倍，50 MHz 下全约束满足，并在实板上完成 50 帧逐帧与 TFLite 参考核完全一致的验证。

## 1. 数据采集与清洗

### 1.1 采集规模与来源

全部数据来自实车在帆布赛道上的人工驾驶录制，摄像头为车体前向单目相机。

| 来源           | 帧数              | 用途                       |
| -------------- | ----------------- | -------------------------- |
| 主赛道 session | 4523              | 连续整圈行车，覆盖全部弯型 |
| 定点补采 ×4    | 21 / 51 / 57 / 65 | 补足个别连续失败点位       |
| 直行样本补充   | 964               | \|angle\| < 0.08 直行帧    |
| **合计**       | **5673**          | 清洗后进入训练             |

主 session 提供整圈连续性；四个补采片段针对具体失败路段做短时重录；直行补充帧专门解决「原始数据直行占比不足、模型在直道乱打角」的问题，只取直行样本，不引入其他弯道数据。

清洗后按真值角度分箱的实际分布如下（分箱边界 `[−1.01, −0.5, −0.2, −0.05, +0.05, +0.2, +0.5, +1.01]`）：

| 急左 | 中左 | 小左 | 直行 | 小右 | 中右 | 急右 |
| ---- | ---- | ---- | ---- | ---- | ---- | ---- |
| 453  | 336  | 503  | 996  | 540  | 534  | 2311 |

急右单箱占 40.7%，是这套数据最主要的类别不平衡来源；直行箱虽经补充达到 996 帧，但仍是「幅值小、容错低」的高风险箱。

### 1.2 标签清洗三步

人工打角标签在时间与幅值两个维度上都带噪声，因此清洗分三步，逐步把标签对齐到图像事件：

**① 时间对齐（τ 扫描）**

驾驶员看到弯道后通常隔 1–2 帧才打角，出弯回正同样滞后。做法是用一个已收敛的参考模型对每个 session 做「预测序列 vs 标签序列」的 τ∈[−3, +3] 帧扫描，只有 MAE 改善超过 2% 才应用平移，否则保持 τ=0 不动。这一操作只把标签搬到与视觉事件对应的帧上，**不会删掉预判性提前打角**——预判是真实驾驶意图，需要保留。

**② 中值滤波（窗口 5）**

手柄抖动表现为孤立的 1–2 帧尖峰，被中值窗口直接抹掉；预判性提前打角通常持续 ≥3 帧，中值滤波保边，完整保留。这样同时满足「去抖」与「保留预判意图」两个目标。

**③ 剔除修正帧**

打角过冲后 1 帧内急速反向拉回的帧是毒样本：图像几乎没变，标签却反向跳变。判定条件为连续两帧跳变幅值都大于 0.3 且方向相反，命中即剔除该帧。渐进预判与弯道入口的快速同向打角不会误伤。

三步清洗后得到 5673 帧训练池，评估用的 4717 行车帧从中逐帧对齐抽取。

### 1.3 分箱均衡过采样

过采样只作用于训练集，验证集保持真实分布以免评估失真。目标箱数与实际分布对比如下：

| 分箱       | 急左 | 中左 | 小左 | 直行 | 小右 | 中右 | 急右 |
| ---------- | ---- | ---- | ---- | ---- | ---- | ---- | ---- |
| 清洗后实际 | 453  | 336  | 503  | 996  | 540  | 534  | 2311 |
| 过采样目标 | 1200 | 1200 | 1000 | 1000 | 1000 | 1000 | 1500 |

急左／中左抬到 1200 帧，用于修正左转方向打角不足；急右封顶 1500 帧，对 40.7% 的原始占比做轻度压制，避免其淹没其他分箱。重复帧在每个 epoch 会经历不同的随机增强，等价于持续生成新样本。

## 2. 模型架构与 FPGA 约束

架构不是自由设计的结果，而是从 PG2K100 的片上存储预算反向推出来的。约束链条是：未经裁剪与降采样的标准 Donkey 网络把 95×156×3 直接展平后接 Dense，INT8 体积约 816 KB，需要约 182 块 BRAM（超过 144 块上限的 126%），根本放不下。因此做了两处结构性收窄：

- **真裁剪输入**：取传感器 ROI `RGB[25:120, 2:158, :]` → 95×156，而不是把整幅图缩放。配合三级 stride-2 下采样，Flatten 输入从 9600 降到 **960**，Dense1 参数从 665,600 降到 96,000。
- **收窄最后一层卷积**：Conv5 输出通道 64→16。此时特征图已缩到 5×12，64 通道信息高度冗余，收窄后省 3 块 BRAM，整卷精度损失在可接受范围。

最终结构：

| 层       | 配置                    | 输出尺寸 | 权重 ROM（BRAM 块）   |
| -------- | ----------------------- | -------- | --------------------- |
| Conv1    | 3→24, 5×5, stride 2     | 46×76×24 | 1                     |
| Conv2    | 24→32, 5×5, stride 2    | 21×36×32 | 5                     |
| Conv3    | 32→64, 5×5, stride 2    | 9×16×64  | 12                    |
| Conv4    | 64→64, 3×3, stride 1    | 7×14×64  | 8                     |
| Conv5    | 64→16, 3×3, stride 1    | 5×12×16  | 2                     |
| Flatten  | 960                     | —        | —                     |
| Dense1   | 960→100                 | 100      | 21                    |
| Dense2   | 100→50                  | 50       | 2                     |
| Dense3   | 50→2（angle, throttle） | 2        | 1                     |
| **合计** | **219,732 参数**        | —        | **52 / 144（36.1%）** |

补充说明：

- Dense1 的 21 块 BRAM 单块利用率 99.2%，正好落在 BRAM 拼接的最优点上；这是整个设计里最关键的一块，也是选择 960 维展平输入的直接原因。
- 全模型约 1.02 M MAC/帧。瓶颈在**存储**而非算力，因此所有优化围绕「减权重、减激活、保精度」展开。
- 剩余 BRAM 留给流水线 line buffer，数据通路采用 ap_fixed<8,1> 全 INT8 定点流水。
- 表中的 52 块是权重 ROM 估算口径；综合报告里的 DRM36K 占用（93/144）统计对象不同（含激活缓存与流水缓冲），两者不可混算。

## 3. 损失函数：WeightedMSE

标准 MSE 把所有样本一视同仁，但驾驶任务的误差代价高度不对称：大弯欠转意味着冲出赛道，直行小幅抖动几乎无害。WeightedMSE 从两个维度注入这个先验。

### 3.1 分箱代价权重

| 分箱         | 急左 | 中左 | 小左 | 直行 | 小右 | 中右 | 急右 |
| ------------ | ---- | ---- | ---- | ---- | ---- | ---- | ---- |
| angle 项权重 | 2.0  | 1.5  | 1.0  | 2.0  | 1.0  | 1.0  | 1.5  |

急左、直行、急右取 2.0，中左、中右取 1.5。直行给到 2.0 是因为实车上最容易出界的状态不是转不够，而是直道蛇形；油门项不加权，保持原始回归尺度。

### 3.2 门控欠转惩罚

```
under_mask = (|y_true[:,0]| > 0.3) & (|y_pred[:,0]| < |y_true[:,0]|)   # 大弯且幅值不足
angle_sq   = where(under_mask, angle_sq * 2.0, angle_sq)                # 仅欠转样本再 ×2
weighted   = stack([angle_sq * bin_weights, y_sq[:,1]])                 # 权重只作用于 angle
loss       = mean(weighted)
```

门控的意义在于：惩罚**只在大弯且预测偏小时触发**，不会把模型整体推向「处处过转」；与直行 2.0 权重组合后形成「直行要稳、大弯要足」的双端夹逼，而不是单向拉偏。

## 4. 训练策略

| 项目           | 设置                                                   |
| -------------- | ------------------------------------------------------ |
| 初始化         | 迁移自同架构的裁剪输入预训练权重                       |
| 优化器         | Adam，学习率 3e-4 → 1e-6                               |
| 调度           | warmup 3 epochs → cosine 退火                          |
| batch / epochs | 64 / 最多 100，EarlyStopping patience 15（val_loss）   |
| 验证集         | 时间留出 15%（大 session 取尾段，小 session 全进 val） |
| Mixup          | α = 0.2，触发概率 0.2                                  |
| SWA            | 自 75% epoch 起做随机权重平均                          |
| TTA（评估）    | [原图, 水平翻转]，翻转支路角度取反后取均值             |
| 并行 trial     | 两个独立随机种子并行训练，按 val_loss 选优             |

各设计点的作用：

- **时间留出而非随机划分**：行车数据强时间相关，随机划分会让验证集「见过」训练段前后帧，成绩虚高。按时间切尾段 15% 强制考验未见路况，小 session 因帧数太少全部划入验证集。
- **warmup + cosine**：迁移学习起步用大学习率会破坏预训练的低层特征，前 3 个 epoch 线性爬升保护之；cosine 后段自动细化。
- **Mixup**：对「图像↔角度」做凸组合正则，抑制对单帧纹理的记忆，平滑决策面。概率压到 0.2 是为了避免插值把急弯标签稀释成中间值。
- **SWA**：在损失面平坦区取权重平均，平坦极小值对 INT8 量化扰动更鲁棒，这一步同时服务于后面的定点部署。
- **并行双 trial**：小数据 + 大增强下随机种子方差不可忽略，两个 trial 按同一验证口径选优，是几乎免费的收益。

![并行双 trial 选优](assets/fig_f_trial.png)

*图 2 · 两个独立 trial 在同一验证口径下的 WeightedMSE。Trial B 以 0.073194 优于 Trial A 的 0.075255，差距 2.8%，最终选用 Trial B。*

选定模型在时间留出验证集上带 TTA 复评为：角度 MAE 0.19369、相关系数 0.89192、油门 MAE 0.02566。该成绩与第 6 章的 4717 帧整卷口径分布不同，两者不可直接比较。

## 5. 数据增强体系

增强分为四组，共 23 项 + 1 个配对机制。设计原则是**训练分布必须覆盖并超过推理时可能遇到的成像退化面**，且每一项都要有物理成因对应，不做无目的的像素抖动。

| 分组             | 内容                                                                                                                                               | 对抗的失效模式                    |
| ---------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------- |
| 基础几何/光度    | 随机水平翻转关闭（由成对镜像承接）；亮度 ±80；对比度 0.5–1.6；旋转 ±10°；横移 ±15 px；纵移 ±5 px                                                   | 相机安装偏差、车道横向偏移        |
| 光照与成像鲁棒   | HSV 色相/饱和度/明度扰动；γ 0.5–2.0；高斯噪声 σ 0–15；随机阴影多边形（强度 0.2–0.7）；运动模糊（核 7–25，多方向）；cutout 1–4 块；过曝 40%；淡饱和 | 时段/天气光照变化、镜头污渍、抖动 |
| 帆布场地特异     | 局部高光白斑；饱和度褪色；波浪形变；梯形畸变；灯光带状反射                                                                                         | 帆布反光、褶皱弯线、标线老化      |
| 场景干扰         | 合成干扰线 25%（仅 \|angle\|>0.3 触发）；淡化/断线 30%                                                                                             | 邻道线误导、标线印刷不清          |
| 成对镜像（机制） | 训练集每条样本产出 (I, a) 与 (flip(I), −a) 同 batch 入网                                                                                           | 左右方向偏置（急右占 40.7%）      |

几个关键设计点：

- **干扰线带角度门控**：只在急弯帧（|angle|>0.3）叠加。直行帧叠加干扰线会教模型在直道乱打角，反而有害。
- **淡线高频出现**（30%）：帆布赛道标线老化是常态而非偶发，因此给较高触发率。
- **模糊与 cutout 的物理对应**：车身过坎时画面糊一瞬、镜头被污渍遮挡，都是车载场景的高频输入，不是人为加噪。
- **成对镜像替代随机翻转**：随机翻转以 50% 概率独立触发，方向监督是随机的；成对镜像则让原图与镜像图**必然同批出现**，标签严格取反，形成确定性的方向对称约束。代价是随机翻转必须关闭，否则两种机制叠加会打乱配对关系。

实现细节上，几何族统一走仿射矩阵 + `warpAffine`（边界反射或灰 128 填充），避免 `np.roll` 造成的环绕卷绕伪影；光度族严格区分加性偏移（亮度）与乘性增益（对比度/曝光/色温）；模糊用按角度逐点连线并归一化的线核；遮挡族按物理机制分为乘性阴影、硬填 128 的 cutout、向白饱和的灯光带三类。逐项参数与像素级实测对比图见附录 B。

### 6.3 典型片段对照

## 7. 镜像对称性与反向赛道

**为什么要测。** 赛道可以反向跑。一个只在一个方向上训练过的模型，把输入图像水平翻转后，输出应当等变于标签取反：翻转后的急右帧，模型应给出接近 −t 的强左转。这不需要实采反向数据，就能离线量化「换向鲁棒性」。全部 4717 帧都生成了翻转输入，逐帧计算原方向精度、翻转方向精度、失配度与等变相关性。

![镜像对称性诊断](assets/fig_f_mirror.png)

*图 9 · 左：急右帧（t>0.8，n=1705）在原方向与翻转方向的近真率；右：镜像失配度 P + P_f 的分布，理想应集中在 0 附近（绿带为 |失配|≤0.3）。*

| 指标                                     | 数值               |
| ---------------------------------------- | ------------------ |
| 原方向近真率（\|p−t\| ≤ 0.2，n=1705）    | **67.68%**         |
| 翻转方向近真率（\|p_f−(−t)\| ≤ 0.2）     | 11.50%             |
| 翻转方向 MAE                             | 0.4810             |
| 镜像失配 MAE（\|p + p_f\|，理想 0）      | 0.5213             |
| 等变相关 corr(p, −p_f)                   | 0.3076             |
| TTA MAE（全量）                          | 0.3128             |
| 失配帧 @0.3 / @0.4 / @0.5（全量 n=4717） | 3156 / 2623 / 2149 |

结论需要如实说明：**原方向的绝对精度是好的（67.68%），但单侧翻转方向只有 11.50%**。成对镜像确实把统计意义上的对称性拉平了（同批成对出现，失配帧数在后两个阈值上并未恶化），但模型并没有真正学到一个等变的表征——它学到的是「在原方向数据纹理主导下，对配对样本做出平均化响应」。急右数据占 40.7%，翻转侧（等价于急左急弯）的有效多样性反而被压缩，因此翻转分支从未被独立、多样地检验。

这一点直接决定了 TTA 的可用性：由于翻转支路不可信，[原图, 水平翻转] 平均反而会把正确输出拉偏（TTA MAE 0.3128 高于单支路），**当前部署不使用 TTA**，只在评估时保留该指标作为诊断量。

### 8.4 RO-PUF 权重绑定

模型权重在 FPGA 上以「与芯片物理指纹绑定」的形式生效，目的是让同一份比特流换到另一块板子上无法得到正确推理结果。

**响应生成。** 使用 64 个七级环形振荡器，每个振荡器占 7 个原生 LUT；同一时刻只有两个振荡器在工作，计数前先 ÷16 分频，测量窗口为 50 MHz 下的 50,000 个周期。每次比较对 9 次测量做多数表决，只有计数差 |Δ|≥50 的比较才被认为稳定，被排除的比较不参与编码。16 个固定挑战各选出 8 个比较对，每组 8 个多数表决位异或后得到 1 位，共 16×8 = 128 位响应，另加 16 位校验位，合计 144 位。完成一次完整扫描约 1.16 s。

**绑定方式。** 推理在每帧起始锁存一代完整响应，对每个启用的乘加抽头做：

```
negate[d] = SIGN_MASK[d] & (puf_signs[d] ^ BINDING[d])
```

即当该位与嵌入的绑定关系不一致时，把中心化后的激活值取反。作用范围是 Dense1 的 96 个抽头加 Dense2 的 48 个抽头，共 144 个乘加抽头，与 144 位响应一一对应。这个操作**没有身份匹配标志位**：硬件不判断「这是不是授权的板子」，只是让算子在物理上算错——匹配的板子输出与黄金结果完全一致，不匹配的板子得到的是被系统性篡改的算术结果。计数器停摆、溢出或超过 600 MHz 输入工程边界，都按硬件故障处理并停机。

**板级实测。** 绑定板上 8 次重新注册得到 110 个稳定位，独立 holdout 8 次扫描 **0 位失配**；真实断电重启后再次注册，仍是 8 次扫描 0 位失配。换到另一块同型号板子上，同一比特流与 A 板密钥相比每次扫描有 54–57 位失配（91 个双板稳定位中 47 位不同，51.6%），即物理指纹确实区分开了两块芯片。密钥以 32×18 的块 ROM 形式在每次复位后加载，响应本身只存在于 FPGA 的易失寄存器中，不写入车载文件系统或 flash。

## 附录 A · 评估口径定义

- **对齐口径**：4717 帧由主 session 连续帧构成，模型与标签逐帧对齐，全部指标由逐帧 CSV 重新统计。
- **推理预处理**：`RGB[25:120, 2:158, :]` 裁剪 → /255.0 归一化，**不使用 CLAHE**（与 FPGA 部署路径一致）。
- **分箱边界**：`[−1.01, −0.5, −0.2, −0.05, +0.05, +0.2, +0.5, +1.01]` → 急左 / 中左 / 小左 / 直行 / 小右 / 中右 / 急右，按**真值**归箱。
- **行为标记**（严格口径，一帧可命中多条）：欠转 = |t|≥0.5 且 |p|<0.8|t|；过冲 = |p|>|t|+0.3；反向 = |t|≥0.15 且 t·p<0；预判 = |t|<0.08 且 |p|>0.2（非异常）。
- **场景判定**：直行 |t|<0.08；急弯 |t|≥0.5；极限弯 |t|≥0.9；大幅值 |t|≥0.8。
- **急弯欠转率** = 急弯帧中 |p|<0.8|t| 的占比；**直行越界率** = 直行帧中 |p|>0.2 的占比。
- **镜像指标**：急右帧取 t>0.8（n=1705）。原方向近真率 = |p−t|≤0.2 的帧占比；翻转方向近真率 = |p_f−(−t)|≤0.2；镜像失配 = |p + p_f| 的均值；等变相关 = corr(p, −p_f)；TTA 输出 = (p − p_f)/2。
- **「近真率」与「幅值到位率」是两个不同口径**：近真率（|p−t|≤0.2）衡量单帧输出是否够准；幅值到位率（|p|≥0.8|t|）只看转向是否打够、不看方向偏差。正文引用「近真率」，不混用。
- **量化与部署数据范围**：`model_evaluation.json` 与 `integration_validation.json` 的评估集为独立录制的 192 帧样本，只用于证明量化误差与部署链路正确性，不作为实车精度引用。
